# Безопасность

Этот проект строится вокруг **туннелирования приложений** через ADNL на TON и локальный мост SOCKS. Относитесь к развёрнутому узлу как к **доверенной сетевой инфраструктуре**:

- при компрометации **сразу меняйте** `auth_token` и ключи (`private_key` и клиентские ключи);
- на VPS используйте **минимально необходимую** поверхность атаки: файрвол, только нужные порты, мониторинг аномальной нагрузки;
- ограничения на приватные подсети заложены в код egress — см. также [`PROJECT_OVERVIEW_RU.md`](PROJECT_OVERVIEW_RU.md).

## Куда сообщать о уязвимостях

Предполагаемые **уязвимости безопасности** (обход авторизации, RCE, утечки трафика/ключей и т. п.) сообщайте **не** в открытых issues с полным эксплойтом, а конфиденциально:

1. вкладка **Security** репозитория → **[Report a vulnerability](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)** (англоязычный интерфейс GitHub);
2. или по контактам, которые мейнтейнер указал в своём профиле GitHub / в описании организации.

Пожалуйста, приложите воспроизводимые шаги и **хэш коммита** или тег сборки.

Англоязычный ориентир для мейнтейнеров и репортёров: [`SECURITY.md`](SECURITY.md).

## Баги продукта, не связанные с безопасностью

Их можно оформлять через обычный **Issues** на GitHub, выбрав шаблон `.github/ISSUE_TEMPLATE/` (если включён для репозитория).
